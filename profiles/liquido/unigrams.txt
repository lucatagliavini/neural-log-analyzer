# ── Log Guidewire specifici ───────────────────────────────────────────────────
# UNA sola feature per tutti i log applicativi: normalize-query.sh sostituisce
# qualsiasi "<nome>.log" (e i glob quotati) con il placeholder <LOGFILE>, quindi
# il classificatore impara la *forma* "c'è un nome di logfile qui" e non l'elenco
# dei nomi. Prima c'era l'alternanza esplicita dei 15 nomi di APP_LOG_NAMES: un
# modello legato a un singolo deployment (jgroups esiste solo per app con cache
# distribuita) e fragile — ccCanaliz aveva smesso di funzionare per un problema
# di maiuscole. Sul nodo di produzione i log sono 28, la whitelist ne copriva 16.
#
# Minuscolo perché query-to-features.sh:22-23 e vectorize() fanno lowercase.
# Con le parentesi angolari, non `\blogfile\b`: quest'ultimo matcherebbe anche la
# parola "logfile" digitata dall'utente.
<logfile>                   :: 2
coda|queue\b|batch\b        :: 1
\bdice\b|\bcosa.dice\b      :: 1
# \bguidewire\b — rimosso: normalizzato a <APP> da normalize-query.sh
# api / \bdatabase\b / \bmessaging\b / performance.integr / jgroups /
# plugin|ruleengine|studio / velocity — rimossi: erano nomi di log concreti nel
# vocabolario, ora coperti da <logfile>. Le query che li usavano SENZA ".log"
# ("errori nel jgroups log") sono state riformulate in queries_labeled.txt.
