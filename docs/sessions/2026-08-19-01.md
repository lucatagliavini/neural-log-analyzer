# Sessione 2026-08-19-01 — NCLOCAL-1 chiusa: backup, retrain completo via neural-c, bug latente in grep_named_log scoperto e corretto

## Contesto di partenza

`NCLOCAL-1` (aperta il 2026-08-18 validando `USNEXT-1`, priorità Alta): il modello locale
attivo (`nlp/models/intent_classifier/`) non era mai stato convertito al formato
`neural-c` — conteneva ancora i pesi neural-bash (`layer1.txt`/`layer2.txt`/`model.conf`,
datati 7 agosto) mentre `lib/infer.sh` chiama incondizionatamente `neural-c predict`. Ogni
query locale a `chatbot.sh` falliva in silenzio (`2>/dev/null` + `set -euo pipefail`),
causando 29 FAIL nella suite (`test-theme.sh`, `test-srch-named-log.sh`,
`test-profile-config.sh`).

Indicazione esplicita dell'utente per la correzione: backup dei pesi attuali in un'altra
directory, poi retrain completo via `neural-c` per avere tutto convertito localmente;
solo quando la suite locale mostra confidenza adeguata sulle query e i tool associati, si
potrà pensare a un deploy in produzione — il deploy stesso resta fuori scope.

## Lavoro svolto

1. **Backup**: `nlp/models/intent_classifier/` → `nlp/models/intent_classifier.backup/`
   (`cp -a`, prima di ogni altra azione). Coperta dal pattern `.gitignore`
   `**/models/*.backup/`, non tracciata.
2. **Rebuild dataset**: `build-dataset.sh --profile profiles/liquido` → 1086 esempi (il
   numero era 968 in una versione precedente non aggiornata di `CLAUDE.md`).
3. **Reinit + retrain**: `setup.sh --profile profiles/liquido` (`neural-c init --force`,
   topologia `111,48,16`) → `train.sh --profile profiles/liquido` (adam, early stopping
   epoca 635/5000, pesi dall'epoca 535, val loss ≈0.0065). Verificato empiricamente che
   `neural-c init --force` non tocca file preesistenti non suoi (i vecchi artefatti
   neural-bash restano nella directory live, ora orfani — nulla li legge più).
4. **Validazione**: `bash tests/run-tests.sh` — prima corsa post-retrain: **91 PASS / 1
   FAIL** (`test-srch-named-log.sh`, 2 asserzioni su 20). Diagnosticato: bug reale in
   `lib/tools/grep_named_log.awk`, non un problema di fixture (verificato per principio 8
   prima di modificare produzione) — il contatore `matched_format` confondeva "una
   grammatica di `logline_parse()` ha riconosciuto la riga" con "la riga ha un livello di
   severità leggibile". I due concetti coincidevano per caso prima della migrazione a
   `logline_parse()` (Intervento 1 di `USNEXT-1`); dopo, un file access-log (che per
   costruzione non ha mai un livello testuale) contava come "formato riconosciuto" senza
   mai produrre un `row_level`, e il messaggio LOGSEL-1 non scattava più sulla fixture
   dedicata. Corretto sostituendo il contatore con `matched_level` (incrementato solo
   quando `_ll_level != ""`). Verificato che gli altri tre tool migrati nello stesso
   intervento (`tail_named_log.awk`, `tail_log.awk`, `search_all_logs.awk`) non hanno lo
   stesso pattern — il difetto era isolato a questo file.
5. **Suite finale**: `bash tests/run-tests.sh` → **92 PASS / 0 FAIL**. Level 1 (tutte le
   query di classificazione intent) 100% corretto sul tool atteso, confidenze 31%–99%.

`BACKLOG.md` aggiornato: `NCLOCAL-1` chiusa (sezione dedicata, dopo `USNEXT-1`), rimossa
dalla tabella APERTI.
