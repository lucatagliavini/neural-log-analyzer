# Vocabolario bigram (co-presenza) per il profilo "liquido".
# Formato: <patternA> :: <patternB>           (peso implicito 1)
#          <patternA> :: <patternB> :: <peso> (peso esplicito)
# Entrambi i pattern devono essere presenti nella query per attivare la feature.
# L'ordine determina l'indice della feature nel vettore — non riordinare.
# Modificare questo file RICHIEDE rebuild del dataset e riaddestramento.

# ── exception + tempo → filter_errors ────────────────────────────────────────
# `\bor[ae]\b` e non `ora |ore `: gli spazi vengono RIMOSSI dai pattern da
# query-to-features.sh e build_dataset.py, quindi `ora |ore ` diventava `ora|ore`
# e matchava l'interno di **errore** — la co-presenza si attivava su "exception
# ... errore" senza che la query nominasse alcuna finestra temporale.
# Stesso difetto corretto in unigrams.txt (vedi il commento su `\bor[ae]\b`).
exception|eccezion|warn      :: \bor[ae]\b|ultim|recent|stamatt|stanott

# ── lento + servizi → service_times (non slow_requests) ──────────────────────
lent[oaie]|slow|latenz       :: servizi|servizio|soa\b|backend|web.?service

# ── volume + tempo → traffic_volume (non tail_log) ────────────────────────────
volum|andament|picco         :: \bor[ae]\b|ultim|minut|giorn

# ── righe/tail + recente → tail_log (non traffic_volume) ─────────────────────
rig[ah]|tail\b               :: ultim|recent|recenti

# ── log applicativo custom + errore/problemi → grep_named_log (non tail_named_log) ─
# peso 2 per battere unigram errore (peso 2)
# patternA = il placeholder <logfile> prodotto da normalize-query.sh: vale per
# qualsiasi nome di log, non per un elenco (vedi il commento in unigrams.txt).
<logfile> :: errore|errori|warn|filtr|cerca|eccezioni|exception|problem|anomal|incident|cosa.non.va|non.va\b :: 2

# ── log applicativo custom + mostra/riga → tail_named_log (non grep_named_log) ────
<logfile> :: mostr|visualizz|dammi|rig[ah]|ultim|cosa.c.*nel|tail\b

# ── GC + lentezza/latenza → correlate_gc_slow (non gc_stats o service_times) ─
# peso 2 per dominare su gc_stats e service_times
gc\b|garbage|jvm\b|g1gc :: lent[oaie]|latenz|slow\b|impatto|degrada|rallent :: 2

# ── interrogativo su "log" + predicato di esistenza → list_logs ───────────────
# peso 2 per dominare l'unigram search_all_logs "dove.appare|...|in.quali.log"
# (peso 2) e l'unigram show_help "quali.log.sai" (peso 2).
# patternA = la FORMA interrogativa/quantificata sul contenitore ("quali log",
# "che log", "tutti i log"); patternB = il predicato di ESISTENZA.
# La co-presenza distingue "quali log CI SONO" (enumerare i contenitori) da
# "in quali log C'È <token>" (cercare un contenuto): quest'ultima ha patternA ma
# NON patternB, perché il pattern `ci.sono` non matcha "c'è".
# NB: `log.applicativ` NON è in patternA — attivava la riga 216
# (filter_app_errors "quante exception ci sono nel log applicativo").
# Verificato: 0 esempi dei 1026 esistenti attivano la co-presenza.
quali.log|che.log|quali.file.di.log|che.file.di.log|tutti.i.log :: ci.sono|sono.present|present|disponibil|esiston|elenc|lista :: 2

# ── log di sistema nominato + ricerca testuale → grep_named_log (non
# filter_errors/search_all_logs) ──────────────────────────────────────────────
# peso 2 per battere l'unigram cerca|trova|ricerca|search (peso 2, unigrams.txt:143)
# che tirerebbe verso search_all_logs.
# patternA = "server.log"/"gc.log"/"access.log" con IL PUNTO ERE non escapato
# (matcha qualunque carattere, quindi anche lo spazio: copre "server log" senza
# punto — query-to-features.sh normalizza lo spazio nel PATTERN, non nella
# query), non `server\b`/`gc\b`/`access\b`: con `gc\b` la co-presenza si
# attiva anche su "cerca correlazione tra gc e lentezza" (4 esempi di
# correlate_gc_slow, queries_labeled.txt), perché quella query nomina "gc" e un
# verbo di ricerca senza intendere il file. Con ".log" la co-presenza è zero
# collisioni, verificato con `[[ =~ ]]` su tutto queries_labeled.txt e sulle 90
# asserzioni di run-tests.sh — mai in awk, dove `\b` è backspace, non confine
# di parola.
server.log|gc.log|access.log :: <pattern>|cerca\b|trova\b|ricerca\b|search\b :: 2

# ── conteggio + codice di stato → count_status (non traffic_volume) ───────────
# "quante chiamate 503 stamattina" vinceva traffic_volume al 77% con count_status
# secondo al 35%: `chiamata|chiamate` vive nella sezione traffico di unigrams.txt
# (accanto a `traffico|traffich`) ed è genuinamente ambigua — "chiamate lente",
# "chiamate 500" e "quante chiamate al minuto" sono tre tool diversi. Il
# discriminante non è nessuna delle due parole da sola ma la CO-PRESENZA di un
# quantificatore e di un codice di stato: quello è un conteggio per codice, non un
# volume per finestra. Peso 2 per battere l'unigram di traffico.
# patternB ripete i codici con \b per la ragione spiegata in unigrams.txt (senza,
# "5000 ms" li attiverebbe e la co-presenza scatterebbe su una query di latenza).
quant[eo]|quanti|conta|contami|numero :: \b(400|404|500|503|4xx|5xx)\b|status|stato :: 2
